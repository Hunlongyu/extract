# 日志实现与排查

更新日期：2026-09-07。随 0.6.0 加入，日志模块为自有 C++20 / Win32 实现，无额外运行时依赖。

## 使用与定位

每次运行自动创建日志，包括拖拽、多包批次、`--list` 和辅助命令。首选路径由当前 `Extract.exe` 的实际位置决定，与当前工作目录和输入包位置无关：

1. `<Extract.exe 所在目录>\log\`
2. 首选无法建立可写日志文件时，回退当前用户 Known Folder `LocalAppData` 下的 `Extract\log\`。

目录存在但没有读取/创建权限、同名普通文件阻挡、路径经过重解析点等都视为不可用。写入或下一分段创建失败时也尝试回退一次；日志中记录 `log.fallback`。两处均不可写时关闭本次日志写入，向调试输出和可用的标准错误输出简短诊断，继续提取，不弹出阻断对话框。

任务摘要 `%LOCALAPPDATA%\Extract\jobs\<job-id>\summary.txt` 的“详细日志”包含当前会话的文件匹配路径。回退前后日志共享会话 ID；如果中途回退，较早步骤可能仍在原目录。该摘要依旧独立于详细日志，`--open-last-result` 的行为不变。日志路径使用 `*.log` 匹配本次各分段，不是一个可直接双击的单文件名。

## 默认策略

| 项目 | 行为 |
| --- | --- |
| 文件格式 | UTF-8，无 BOM；每行一个完整 JSON 对象，扩展名 `.log` |
| 文件名 | `extract-YYYYMMDD-HHMMSS-GUID-NNNNN.log`，日期时间为 UTC，分段从 00001 开始 |
| 单文件大小 | 2 MiB；写入下一条前轮转，不拆分记录 |
| 目录总量 | 10 MiB；创建分段时预留本分段的 2 MiB |
| 文件数量 | 最多 200 个，防止大量短任务产生过多小文件 |
| 保留期限 | 最后写入时间超过 30 天的旧日志优先删除 |
| 检查时机 | 启动创建分段、轮转、退出，以及持续写日志期间每隔 60 秒 |
| 删除顺序 | 先满足期限要求，并按最旧优先降低总量和数量 |
| 活动文件 | 使用不共享写入/删除的句柄，清理时无法独占打开的文件跳过 |
| 刷新 | 每条直接 WriteFile；错误立即 FlushFileBuffers，普通记录写入时每隔 2 秒刷新，轮转和正常退出时刷新 |
| 超长字段 | 每字段最多保留 4096 个 UTF-16 单元；明确追加 `[truncated]`，不留下半个代理字符或无效 JSON |

程序不安装后台清理服务；程序不运行时没有定时清理。并发活动文件、只读旧文件或其它程序持续持有的文件可能暂时使目录超过限额，后续运行继续清理。单文件限额仍独立生效。保留策略只管理所选日志目录下符合本工具精确命名的普通文件，不递归扫描，不管理 `jobs`、输出文件或其它名称的日志。

单次长任务的日志超过总量时，较早分段也会被清理，保留最近的处理步骤。默认 10 MiB 总量按用户要求设置。

这些是本项目的默认工程策略，不声称存在统一强制的日志大小标准。限额集中在 `src/platform/log.h`，没有新增命令行配置或环境变量覆盖接口。

## 日志字段与解包步骤

| 字段 | 用途 |
| --- | --- |
| `time` | UTC 时间，精确到毫秒 |
| `level` | INFO、WARN、ERROR |
| `session`、`pid`、`tid` | 运行会话、进程和线程；同一批次共享 session |
| `event` | 可检索的事件名，例如 `parse.failed`、`extraction.end` |
| `stage` | 当前操作，例如 `package.parse`、`file.extract`、`cab.decode` |
| `rootPackage` | 当前根输入包的完整路径 |
| `package` | 当前实际处理的包路径，包含自动展开的内层包 |
| `file` | 当前文件或操作对象；载荷相对路径相对于本包输出，哈希阶段记录实际临时文件路径 |
| `message` | 原因、参数、大小、哈希、格式、耗时、状态与原生错误码等 |

日志覆盖：启动与最终退出码、输入批次、格式候选、输入大小、清单解析、数据版本、包校验标志、压缩流初始化、NSIS 固实缓存、Inno 数据块、MSI CAB 媒体、Burn 容器与缺失外置文件、逐文件创建/写入阶段/校验、输出提交与异常回滚、报告写入、内层识别/复用/保留/失败、最终完整或部分完成状态、任务记录和通知结果。

`step.begin` 与 `step.end` 标记阶段起止，结束记录含单调时钟耗时 `elapsedMs`；异常展开时写 `step.aborted`。异常原因在相邻的 `parse.failed`、`input.failed` 或 `nested.failed` 记录中，包含 `status`（映射的退出码）、`nativeCode`、中文原因；可用时附系统错误文本。内层失败保留根包和子包路径，避免只看见外壳名称。

解压后 SHA-256 用于输出复核，`sourceHashVerified` 单独表示是否有包内哈希/CRC 对照；不能把“计算 SHA-256”写成“验证了包内 SHA-256”。NSIS 的包 CRC 单独记录。卸载器保留属于 INFO；原路径未还原的辅助文件不改变已确定的成功判定。正常释放缓存记录 `output.cleanup`，异常回滚记录 `output.rollback`。

## 排查示例

打开本次会话日志，先找最后的 `session.end` 和 `batch.end`。`exitCode=0` 为成功，299 表示部分完成或批次含成功与失败。

- 不支持的安装器或损坏元数据：查 `format.candidate` 和 `parse.failed`，确认进入了哪个解析器。
- 内容校验失败：查 `step.aborted` 的 `file.extract` / `file.verify` / `file.hash`，再看同一包的失败原因与输出回滚路径。
- 外壳成功、里面失败：查 `nested.failed`，其中 `package` 是出错的子包，`rootPackage` 是最初拖入的安装包。
- Burn 在线载荷缺失：查 WARN `burn.payload_missing` 的文件路径，再看 `extraction.end` 中的 `contentComplete=false`。
- 通知没显示：查 `notification.result`；提取结果与通知提交结果分别记录。

`--quiet` 不关闭日志，`--list` 不在标准输出混入日志。文本中的换行、引号和控制字符转义，避免一个恶意文件名伪造下一条日志。日志不自动上传，不记录载荷文件内容或安装脚本正文。

## 实现与验证

`platform/log.*` 管理同步写入、上下文作用域、异常安全边界和保留策略。每次运行独立 GUID 文件，进程内互斥写入，线程上下文彼此隔离。通过真实创建/写入结果选择目录，不仅检查属性；目录链在日志使用期间持有锁并拒绝重解析点。清理先独占打开候选文件，再检查普通文件属性并通过该句柄删除，避免覆盖活动日志或跟随目录链接。

所有日志消息构造与写入位于不向解包流程抛异常的边界内。保持调用者的 Win32 最后错误值；不使用已加日志的输出模块写日志，避免递归。失败的记录构造可以丢弃单条，文件写入失败会回退或停用。系统强制终止或断电不保证最后一条完整落盘，硬崩溃转储与 worker 隔离不在本次实现中。

`log_integration` 使用独立限额较小的日志探针和已知内容的 ZIP/CAB/Burn 数据，覆盖分段大小、目录总量、数量与过期清理、非本工具文件保护、活动文件保护、真实 ACL 拒绝写入、目录连接拒绝、启动及轮转回退、两处不可写、并发进程隔离、中文与控制字符、超长记录、日志构造异常、包失败、内层失败、Burn 缺失载荷、批次状态、任务摘要定位及 `--list` JSON 兼容。仅修改新建测试目录的 ACL，并在 finally 中恢复；不执行生成的安装器或提取出的程序。

2026-09-07，最终 Debug 与 Release 构建的 8 项 CTest 均通过，包含以 14 MiB 旧文件验证发布程序默认 10 MiB 清理上限。ECHO NEXT、Pebble、Textify、vic-diary、XnViewMP 五个用户样本全部返回 0；各层共 1637 个文件的相对路径、大小及 SHA-256 与 0.5.1 逐项一致。7z 载荷另核对官方工具的清单/CRC，Inno 另核对包内摘要。数据见 [0.6.0 验证记录](data/validation-0.6.0.json)。本轮使用静态提取与 `--quiet` 验证，没有运行安装包、输出应用或执行通知横幅的视觉验收。
