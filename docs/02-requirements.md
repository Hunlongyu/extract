## 2. 核心体验

1. 用户打开便携目录，将一个或多个安装包拖到 `Extract.exe` 或指向它的快捷方式。
2. 程序读取文件内容，自动选择本项目的解析模块。
3. 在源文件旁建立独立临时目录，提取并校验包内文件。
4. 完成后得到 `<文件名去扩展名>_extracted` 目录。
5. 发送一条系统通知，点击打开结果目录；失败或部分完成时点击打开任务记录目录。

示例：`D:\Downloads\Editor-Setup.exe` → `D:\Downloads\Editor-Setup_extracted\`。

处理时没有控制台闪窗；不启动输入安装器或提取出的程序。双击无参数启动时通知用户将安装包拖到图标上，然后退出。

## 4. 近期兼容策略

- 样本窗口暂定 2021–2026，最近两年和当前稳定版优先。
- 初始结构目标：Inno 6.2–6.7、7.0/7.1；NSIS 3.x Unicode；近期软件的标准 MSI。
- 自有程序先支持 Windows 10 22H2 / Windows 11 x64；载荷的 x86/x64/ARM64 架构作为数据处理，不据此启动不同的安装程序。
- 不根据文件创建日期、签名时间或扩展名直接认定安装器版本；以实际结构和能力为准。
- 新发布但使用较老打包结构的软件，若具有近期实际需求，可增加最小兼容分支，优先级高于纯历史收藏样本。
- 同一产品只更换图标或 UI，不等于格式变化；相同营销版本号也可能存在不同结构或第三方修改版。
- 每种格式对外列出已测结构、编译选项和失败限制；未测试的组合标记为待验证。

## 5. 文件与目录规则

### 输出位置

默认在源文件旁建立结果目录；无权写入时明确失败，允许用 `--output` 指定其它父目录，不静默改位置。已有同名目录时依次使用 `_extracted (2)`、`_extracted (3)`，不合并、不覆盖。

先写入本任务独占的同卷临时目录，通过校验后提交最终名称。原安装包保持不变；异常清理只触及能确认归属的临时目录，不能跟随链接删除其它位置。

### 逻辑目录

Inno 保留 `app` 等逻辑根；MSI 将系统目录标识放在输出树内；NSIS 将可解析的目标目录映射到输出树。不会把包中描述的 `ProgramFilesFolder` 或系统目录写入本机真实安装位置。

同一路径存在多种组件、架构或条件分支时，不任意选择一个覆盖其它文件。保留全部可读载荷，冲突条目放入带稳定条目 ID 的 variants 目录，记录原目标、条件和映射关系。未知目录项进入 unresolved 目录并报告部分/路径未还原。

### 嵌套包

只对已经验证的封装规则自动展开内层，例如明确识别的 Electron/NSIS 应用归档。保留原始内层包，展开结果放独立目录，记录父子关系。普通应用的数据文件和 `app.asar` 不因“也能解析”就自动递归。

0.5.0 最多 4 层、32 个包（均含根层），整个根任务共享 8 GiB / 10000 文件的展开预算；时间硬上限仍待实现。达到限制时保留已提取文件并显示“仅完成部分层级”，不误报完整完成。通用递归开关留待后续。

## 6. 结果定义

| 状态 | 条件 | 用户看到的内容 |
| --- | --- | --- |
| 完成 | 本次范围内可静态读取的载荷均已提取，必要校验通过 | 文件提取完成，文件数和输出位置 |
| 仅外层提取 | 外层解开，存在未处理或不支持的内层安装包 | 已提取外层文件，内层内容尚未展开 |
| 部分完成 | 已得到部分文件，但存在缺失、未解析路径/分支、校验错误或限制 | 文件未完整提取，并指出原因 |
| 需要外部内容 | 文件清单要求远程载荷、缺卷或差分基线 | 需要对应文件，无法从当前包完整还原 |
| 暂不支持 | 识别出类型但尚未实现该结构，或没有支持的容器 | 当前版本暂不支持此安装包 |
| 失败 | 损坏、I/O 错误、解析异常、超时等 | 解包失败或已停止，并给出可理解原因 |

完成表示包内文件提取结果，不代表完成安装或软件一定可以便携运行。仅发现 PE 图标、资源、节或未知 overlay，不能判为安装包解包完成。

卸载器不属于解包工具必须还原的应用载荷。0.5.1 起，按包结构识别到的卸载器作为辅助文件保留，不因其原始目录未还原而报告部分完成；安装时才生成的卸载器也不要求生成。普通文件、未知内容不能仅因名称含有 uninstall 就被排除。应用载荷缺失、损坏、路径未还原或内层提取失败继续如实报告。若本层 app 目录只有卸载辅助文件，应优先打开已完整提取的内层应用目录。

合法空归档可报告“包内没有文件”；未知 EXE 或安装器缺少预期数据时不能用此状态掩盖错误。缺失未嵌入的在线载荷不能被合成出来，首版不联网下载它们。

## 7. 通知与便携行为

普通静音系统通知，不抢焦点。批次结束后统一显示完成、部分、失败数量。点击单个成功结果打开输出目录，其它情况打开任务记录目录；只有用户点击时才打开 Explorer。

采用当前用户范围的 AUMID、带占位 CLSID 的通知快捷方式与 `hunlongyu-extract` URI 协议注册。通知使用协议激活，不注册常驻 COM 服务器。移动后下一次发送通知或运行 `--repair-notifications` 更新路径；旧位置被删除且未修复时，旧通知可能失效。`--quiet` 和 `--list` 不修复通知注册。

通知接口参考微软的 [Desktop Toasts 示例](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/desktop-toasts/)，采用其[桌面应用通知文档中的占位 CLSID 与协议激活方案](https://learn.microsoft.com/sv-se/windows/apps/develop/notifications/app-notifications/toast-desktop-apps)。便携意味着解压运行，不意味着完全零用户级注册痕迹。

系统通知被关闭或免打扰时，不自动改用消息框；结果写入本地记录，并提供 `--open-last-result`。通知提交成功不等于用户已经看到横幅。

## 8. 日志与辅助命令

任务摘要：`%LOCALAPPDATA%\Extract\jobs\<job-id>\`，包含本次详细日志位置。输出目录中的 `_extract-report.json` 保留结构化提取结果。

0.6.0 起，详细过程日志优先放在程序同级 `log`，无法读写时回退 `%LOCALAPPDATA%\Extract\log`；写入中途失败也尝试回退。记录输入标识、格式/数据版本、父子包关系、逐文件提取和校验、失败阶段与原因、系统错误码、输出位置及耗时。默认 UTF-8 JSON Lines，每次运行独立文件，2 MiB 轮转、10 MiB 总量、200 个文件及 30 天保留；程序运行时自动检查清理非活动日志。日志不自动上传，也不写入载荷内容。两处日志不可用不改变解包结果。策略与活动文件例外见 [日志实现](15-logging.md)。

当前已实现以下命令，输入范围以 README 的已验证格式为准：

```text
Extract.exe "D:\Downloads\setup.exe"
Extract.exe --output "D:\Unpacked" "D:\Downloads\setup.exe"
Extract.exe --list "D:\Downloads\setup.exe"
Extract.exe --quiet "D:\Downloads\setup.exe"
Extract.exe --open-last-result
Extract.exe --repair-notifications
Extract.exe --unregister-notifications
Extract.exe --version
Extract.exe --help
```

`--output` 指输出父目录；`--list` 仅读取并列出，不写载荷。命令行使用者应显式等待 GUI 子系统进程结束再读取退出码。

## 9. 验收范围之外

不执行安装脚本、MSI 自定义动作、注册表导入、驱动安装或载荷程序；不模拟整台 Windows 的安装环境。在线下载、保护壳、密码破解、只有差分数据却没有基线的完整还原，都不属于本次承诺。

老旧格式不建兼容矩阵；支持近期包也不意味着必须还原任意安装脚本在所有运行环境下生成的文件。可静态读取内容与运行时生成内容在记录中分别说明。
