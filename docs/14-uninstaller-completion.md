# 卸载辅助文件与完成状态

日期：2026-09-07。对应 Extract 0.5.1。

解包工具以提取应用载荷为目标，卸载器不属于必须还原的应用文件。之前 vic-diary 的应用归档已完整展开，但 NSIS 外层卸载器的原始目录无法静态确定，使整个任务显示部分完成。0.5.1 将卸载辅助文件的路径问题从完成条件中排除。

## 行为

- 已识别的 NSIS 卸载器保留原始文件和 SHA-256，不递归展开，不要求恢复其安装时目录。
- 只有卸载器存在目录问题、其余载荷及内层完整时，显示提取完成，退出码为 0。
- 通知直接打开完整的应用结果。外层 app 目录若仅包含卸载器，不优先于真正的内层应用目录。
- NSIS 的单一内嵌 ZIP/7z 完整展开，且外层 app 没有应用 EXE 时，也优先打开内层结果，避免停在仅含图标等资源的目录；外层含应用 EXE 时保留原来的 app 目录优先级。
- 普通载荷的未知目录、缺失来源、损坏、内层失败和预算限制继续触发部分完成或失败。
- 卸载器按包头结构识别，不按名称判断。普通程序改名为 `Uninstall.exe` 仍按普通载荷处理。
- 安装时生成的 Inno/NSIS 卸载器继续无需生成；不执行安装器、卸载器或提取出的程序。

文件保留在 `_unresolved` 并不必然表示应用不完整。卸载器仍可在那里作为辅助文件保存；不会为了改变提示删除已有输出，也不会改写过去的任务记录。

## 报告

| 字段 | 含义 |
| --- | --- |
| 文件 `pathResolved` | 该文件的原始目标路径是否静态还原 |
| 文件 `role` | `payload` 或已识别的 `uninstaller` |
| `pathsResolved` | 所有原始路径是否还原，继续保留事实 |
| `requiredPathsResolved` | 除已识别卸载器之外，需还原的路径是否完整 |
| `contentComplete` | 清单要求的内容是否均存在 |
| `nestedComplete` | 已识别的内层是否完整处理 |

最终完成条件为 `requiredPathsResolved && contentComplete && nestedComplete`。卸载器分类在实际文件提取后进行；识别时保持输入句柄，并复核提取阶段记录的 SHA-256。没有逐文件原因的处理器不会被这一例外自动判为完成。

`--list` 仍只列本层元数据，不保证已经分类解压流内的卸载器。最终文件角色和整体状态以提取完成后的报告为准。

## 验证方法

`tests/nested_integration.py` 使用官方 NSIS 编译器的 `!uninstfinalize` 导出真实卸载器测试文件。编译期间只复制文件，不运行生成的安装器或卸载器。新增以下场景：

1. 内层应用完整、外层卸载器目录未知：成功，辅助文件逐字节保留，打开内层应用目录。
2. 卸载器和普通应用文件同时有未知目录：继续部分完成。
3. 普通程序仅命名为 `Uninstall.exe`：不豁免其路径问题。
4. 卸载器位于外层 app，而应用在内层：打开内层应用目录。
5. 多层包装中的卸载器路径问题：成功状态正确向上传播。
6. 卸载器目录未知，但内层载荷损坏：继续部分完成，保留损坏原因。

归档测试另覆盖 ZIP/7z 的 4 个目录选择场景：外层 app 只有图标时打开内层；外层另含应用 EXE 时仍打开外层 app。辅助资源始终保留。

既有 Inno 动态路径、NSIS 安装时生成卸载器、Burn 在线缺失、损坏输入和递归预算用例继续回归。真实安装包通过 `tests/verify-installers.py` 逐文件比对大小和 SHA-256，7z 另外核对官方工具清单和 CRC，Inno 另外核对包内摘要。

Debug、Release 的 7 项 CTest 均通过；最后补充的归档目录选择用例在两种构建再次通过。

| 真实样本 | 应用归档文件数 | 各层累计文件数 | 退出码 | 主要结果目录 |
| --- | ---: | ---: | ---: | --- |
| vic-diary 2.0.0 | 90 | 100 | 0 | `app-64_extracted` |
| ECHO NEXT 26.8.2 | 430 | 441 | 0 | `app-64_extracted` |

| Textify | — | 6 | 0 | `app` |

五个样本的输入摘要、各层文件路径、大小和 SHA-256 与 0.5.0 逐项一致。本轮改变的是完成判定和结果目录选择，已有载荷没有删除或替换。五份新任务记录的成功摘要及 `open-target.txt` 均已读回核对；vic 与 ECHO NEXT 的目标均为实际应用归档输出目录。测试使用 `--quiet`，未做通知横幅点击的视觉验收。

真实样本结果见 [0.5.1 验证数据](data/validation-0.5.1.json)。开发构建和静态文件验证不等于安装效果或软件运行验收；本轮不启动输出中的应用。
