# 大安装包与资源处理

## 用户行为

不再使用统一的 512 MiB 输入、8 GiB 输出和 10,000 文件阈值，也取消 MSI 单个 CAB 256 MiB、MSI/Burn 外置输入累计 512 MiB 阈值。正常大包按实际内容处理；没有设一个更大的固定数字代替旧阈值。

这不代表支持无限大小或所有安装器版本。格式的字段宽度、系统 API、可用地址空间、内存及磁盘仍是实际边界。失败日志应指出具体原因，不把资源不足误报为格式不支持或损坏。

## 读取、缓存与写入

- `io::Input` 用 64 位保存文件大小，提供有边界检查的分块读取和复制。MSI 识别只读文件头；松散源文件使用 64 KiB 缓冲复制，不映射整个载荷。
- 需要随机访问的现有解析器仍按需建立完整只读映射。格式探测后先释放探测映射，再建立解析映射，期间保持输入读锁，避免重复占用地址空间或允许中途替换文件。
- **尚未把所有格式改为滑动窗口解析。** x86 无法处理需要超出其连续地址空间的输入或固实缓存；超出 `size_t` 的大小在转换前拒绝，映射失败明确提示使用 x64 / ARM64。x64/ARM64 同样可能因地址空间或系统资源不足失败。
- MSI 内嵌 CAB 与 NSIS Solid 使用共享的临时磁盘缓存，分块写入，不再把完整内嵌 CAB 堆积到 `vector`。缓存保持原始读写句柄和父目录锁，映射时不重新打开文件；退出或失败按已创建清单清理。
- 每层提取前，将清单预计输出与目标卷当前可用空间比较。7z 固实缓存分配前检查临时卷空间；MSI/NSIS 流式缓存周期检查空间，写入失败保留真实 Windows 错误码。
- 空间检查不预留磁盘配额，其他程序也可能同时写盘。最终仍以写入结果为准；报告“磁盘空间不足”，当前未提交层回滚，已提交父层保留并标记部分完成。
- 内存分配失败单独报告“系统内存或地址空间不足”。批量文件写入后，报告替换针对短暂占用只重试原始句柄，不改变权限或跟随新的路径。

Inno 外置分卷逐卷只读打开、以 64 KiB 缓冲读取，每次仅拼接一个压缩块到临时磁盘文件，再交由现有解码器处理；仍需要该压缩块的连续映射地址空间。CAB 卷链各卷仍受 Windows FDI 有符号 32 位定位约束，整条卷链保留 64 MiB 文件表/名称元数据预算。MSI 内嵌卷链会同时保留相关压缩 CAB 缓存至提取完成；这不等于把解压结果全部放入内存。详见 [分卷实现](26-split-volumes.md)。

## 保留的保护

| 保护 | 原因 |
| --- | --- |
| 文件偏移、长度和累计大小溢出检查 | 使用 Windows 有符号 64 位文件位置范围，拒绝无效声明；这不是应用包体积预算 |
| 数量与序列化内容核对 | ZIP 条目必须容纳于实际中央目录，Inno 表计数必须与实际元数据范围匹配；不能只信任声明数量 |
| 路径、重解析点、覆盖及校验和检查 | 防止写到目标目录以外，发现损坏或被替换的输入 |
| 4 层、32 包及活动链摘要检测 | 防止自动递归无限展开；这些是自动递归边界，不是单包文件数量上限 |
| 元数据、字典与解析工作量预算 | 防止异常声明耗尽内存或让解析器无限工作，仍独立于输入/输出字节量 |

具体仍包括 ZIP/7z/Inno/NSIS 的 64 MiB 级元数据预算、256 MiB LZMA 字典/7z 辅助解码预算、Burn XML 8 MiB 与容器/输入数量限制、NSIS 指令及字符串分析预算。它们并非整进程内存硬限制，也不保证任何大小的合法元数据都能处理。Windows FDI 使用有符号 32 位定位；超出接口范围的 CAB 会明确提示，不截断偏移。

MSIX/APPX 继续使用 ZIP 的只读连续映射，载荷按 64 KiB 块解码和校验。单份 XML 限 16 MiB、500,000 节点与 64 层；Bundle 继承全树 4 层/32 包自动递归保护。详见 [MSIX 资源和校验边界](25-msix-appx.md)。

v0.7.0 发布后的本地实现增加进程隔离、通知取消和可选单包超时（默认关闭），详见 [工作进程与取消](22-worker-cancellation.md)。取消输出总量阈值后，小输入也可能展开很多数据，当前通过实际空间检查及写入错误处理资源不足，不使用固定压缩比拒绝正常内容。

## 回归验证

本阶段增加 `large_integration` 时全部工具齐备共 9 项；后续功能加入后当前共 14 项，见 [构建文档](05-build-and-development.md)：

- 实际提取 513 MiB 载荷的 ZIP，确认输入超过 512 MiB，逐块生成、提取后比较 SHA-256。
- 实际提取 10,001 个文件；嵌套测试另验证根任务累计 10,001 文件仍完成。
- `path_policy` 用稀疏文件验证 5 GiB 偏移读回、越界拒绝、64 位累计溢出和磁盘空间不足。
- 7z 仅列目录用例验证 9 GiB 声明在 64 位下可表示，在 x86 下明确拒绝；损坏的巨量声明仍有独立反例。

可额外执行磁盘压力和 MSI 大流测试，均不运行安装器或载荷：

```powershell
# 写出并校验 8 GiB + 1 MiB 的 ZIP64 载荷，测试后清理大文件，仅保留验证记录。
python tests/large_integration.py --executable out/build/win-x64-release/bin/Extract.exe --work-root out/large-stress-x64 --large-output

# CAB 使用合法尾部填充超过 512 MiB；比较 MSI 内嵌/外置 CAB 提取出的已知文件哈希。
pwsh -NoProfile -File tests/integration.ps1 -Executable out/build/win-x64-release/bin/Extract.exe -WorkRoot out/large-msi-x64 -LargeCab
```

压力测试不默认加入 Actions 的普通回归，避免托管 runner 磁盘容量影响该项验证。ARM64 运行验证仍需 ARM64 环境，不能用 x64 构建或测试替代。

2026-09-07 验证完成：x64 / x86 Release 各 9 项 CTest 全部通过，无跳过；两个架构的 `-LargeCab` 扩展模式均通过。x64 实际提取并校验 8,590,983,168 字节（8 GiB + 1 MiB）的 ZIP64 载荷。两架构的静态 CRT、PE 架构及系统 DLL 依赖检查通过，便携目录 EXE 与测试程序摘要一致。详见 [验证记录](data/validation-large-packages.json)。
