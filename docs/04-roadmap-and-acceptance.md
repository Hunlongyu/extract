## 1. 交付目标

0.2.1 样本反馈补充：Textify 使用的 `6.1.0 (u)` 结构已实现，官方 6.2.2 生成包纳入测试。v0.7.0 已进一步适配选定的 6.3/6.4 等结构，当前精确范围见 [Inno 兼容性](20-inno-compatibility.md)。

交付无主界面的 Windows 便携解包工具。用户拖入安装包后，由本项目模块完成识别、文件规划、解压与校验，右下角系统通知结果。

核心目标为近期 MSI、Inno Setup、NSIS / Electron；基础 ZIP/7z/CAB 支撑各格式和嵌套提取。后续扩大到 MSIX/APPX、Burn、Velopack/Squirrel 的近期离线结构。历史安装器不纳入开发指标。

## 2. 分阶段工作

工时为一名熟悉 Windows C++ 开发者的粗略人日估计，假设已有公开结构/参考实现、基础解码库可用。不把安装包解析误算成单纯的 CLI 包装；需完成 M0 的格式验证后重新估计，尤其是 Inno 7 与 NSIS 变体。

| 阶段 | 交付 | 估计新增人日 | 退出条件 |
| --- | --- | --- | --- |
| M0：研究与格式原型 | 选定近期样本、格式结构说明、Inno 7 和 NSIS 当前版本元数据读取实验 | 2–4 | 能说明文件表/载荷位置和版本差异，明确基础库接口与未解决问题 |
| M1：原生基础 | CMake、Win32 入口、有界输入、统一输出、基础归档、worker、通知基础 | 3–5 | 从拖拽到提取基础包、记录结果和发通知闭环完成 |
| M2：MSI | 本项目表关联、CAB 和松散文件提取、逻辑目录映射 | 4–7 | 内嵌/外置媒体、中文路径、文件名和哈希基准通过；可交付首个原生可用版 |
| M3：Inno | 当前 6.7/7.1，随后补齐目标窗口内结构差异 | 6–10 | 当前稳定版的主要压缩和 32/64 位样本通过，保留可追溯条件变体 |
| M4：NSIS / Electron | 原生索引/字符串/文件指令、压缩适配、受限嵌套展开 | 6–10 | NSIS 3.x、近期 Electron 离线封装、多架构载荷验证通过 |
| M5：核心版验证 | 通知退出后点击、移动修复、异常样本、干净环境发布包 | 4–7 | 核心验收清单完成，发布已测范围与限制 |

M0–M5 算术合计为 **25–43 人日，约 5–9 个工作周**，属于规划区间，不是完成期限。M1/M2 完成即可使用相应格式，不需要等所有格式一起交付。若最新结构验证出现未覆盖的压缩/加密方式或大量动态路径，单独估算，并先发布已验证能力。

扩展阶段预留约 10–20 人日作为初始预算，先 MSIX/APPX，再 Burn 和近期更新框架；M0 的调查结果与真实需求可调整顺序。只有完成对应样本验证后才给该格式正式支持标记，不把预算当成全覆盖保证。

## 3. 各阶段的实现重点

### M0：降低结构不确定性

- 把用户提供的参考仓库、生产方源码和基础库分开记录，固定拟使用的 tag/提交与许可。
- 建立小型格式研究笔记：探测标识、布局、字节序、长度、校验、文件映射、外置媒体、已知差异。
- 优先证明近期 Inno 7 / NSIS 数据的定位和读取路径，避免先做很多 UI 后才发现格式未能解析。
- 测试包由已知文件构建；开发阶段可以使用打包器和参考工具作对照，它们不进入本产品运行链路。

### M1/M2：尽早获得真实原生产品

- 自有代码完成输出规则和结果模型，压缩基础库只读写受控流。
- MSI 利用 Windows 数据库 API 读记录，本项目处理 File / Component / Directory / Media 的关系。
- 已完成的 MSI/CAB/基础归档能力发布为内部试用版，收集近期样本中的真实失败。

### M3/M4：集中覆盖常见安装器

- Inno 按实际结构族实现，最新稳定版优先；包含头部压缩、数据块、solid、外置卷和未知路径。
- NSIS 实现受限静态文件规划，不引入脚本执行环境；动态路径和插件生成内容明确保留为限制。
- Electron 测试要核对最终应用载荷，不能只对外层的若干文件数做比较。

### 扩展阶段

- MSIX：清单、块校验与 Bundle 中内嵌包。
- Burn：内嵌/分离容器、载荷映射与已有模块的递归处理。
- Velopack/Squirrel：近期离线完整载荷、完整更新包；差分包单独分类，缺少基线时不承诺还原。

## 4. 近期样本矩阵

建议初始核心样本 30–50 个，随后逐步增加。重点是覆盖不同结构与选项，而不是收集许多同一打包配置的版本。样本记录来源、软件发布日期、打包结构、SHA-256、预期文件清单和结果层级。

| 类别 | 最小组合 |
| --- | --- |
| Inno | 6.2–6.7 的代表结构、7.0/7.1；当前 x86/x64 安装器；LZMA/LZMA2/Deflate/bzip2；solid、外置卷、中文、多条件同目标路径 |
| NSIS | 3.x 主线当前版与窗口内代表版；Unicode、常见压缩、solid/non-solid、静态/动态目录、修改版样本 |
| Electron/NSIS | 当前稳定 electron-builder 生成的离线包、近期真实软件、多架构、内层归档；另设 nsis-web 反例 |
| MSI | 近年 WiX/InstallShield/Advanced Installer 生成的样本；内嵌/外置 CAB、跨 CAB、松散源、长短文件名、同目标路径组件 |
| 基础归档 | ZIP/ZIP64、7z 目标编码子集、CAB；空包、超过 4 GiB 的相关场景、嵌套归档 |
| MSIX 扩展 | 单包、Bundle、多架构、资源包、块校验错误、缺少外部内容 |
| Burn 扩展 | 不同已发布结构版本、内嵌/分离容器、混合 MSI/EXE、远程载荷 |
| Velopack/Squirrel 扩展 | 分别选择近期离线 setup、完整包、差分包和缺失基线 |

真实包来自软件官方发行位置，取样时核对其当前打包格式。文件较新的软件可能仍用旧结构，记录真实事实，不根据软件名称或文件修改时间推断。软件打包器和样本生成工具的版本纳入报告。

样本不运行安装流程、不自动上传；仓库优先保存可复现的测试脚本与自制无敏感样本，第三方大包只保存来源和摘要。

## 5. 验收指标

### 自主实现

- [ ] 从干净发行目录运行，无 lessmsi/innoextract/UniExtract/7z 等外部解包程序。
- [ ] 格式识别、文件规划、版本适配和目录映射可以定位到本项目源码。
- [ ] 第三方依赖只包含已记录的原生基础库与必要系统组件。
- [ ] 不把完整外部安装器解析模块改名后当作自主实现。

### 文件正确性

- [ ] 原安装包哈希前后一致。
- [ ] 已知原始文件的相对路径、内容哈希及条目映射正确。
- [ ] 目录/条件/架构冲突保留全部可读变体，不覆盖后假报成功。
- [ ] 缺卷、加密、损坏和未知结构分别报告，普通 PE 资源不算载荷完成。
- [ ] 已知嵌套包展开到约定层级，保留原始子包；超过预算或不支持内层时准确标注。

### 使用体验

- [ ] 拖到 EXE / 快捷方式、中文和空格路径、多文件输入通过。
- [ ] 默认输出命名清楚；重复运行、并发同名提交不覆盖旧输出。
- [ ] 无控制台闪窗，成功失败的系统通知有可理解文案。
- [ ] 程序退出后通知点击有效；移动后重新启动能修复注册。
- [ ] 通知关闭/免打扰时不弹阻塞框，可主动查看最近结果。

### 稳定性与边界

- [ ] 超时或主进程退出时回收本项目 worker。
- [ ] 损坏计数/偏移/长度、超大字典、CRC 错误、路径穿越和链接输入测试通过。
- [ ] 按实际资源处理大包、校验累计整数范围，并保持嵌套深度/数量及循环保护；不设置统一输入/输出体积和文件数上限。
- [ ] 清理临时目录不跟随重解析点；输入替换和输出路径竞争得到处理。
- [ ] Release 在目标 Windows 的干净环境完成运行验证，公布未覆盖场景。

## 6. 覆盖率与质量报告

“尽可能支持近期安装包”通过固定样本集衡量，不按广告中的格式数量衡量，也不在尚无样本时承诺 90%/99%。

同时报告：

1. **目标范围完成率**：选定核心结构样本中，完整提取的数量/总数。
2. **近期软件样本完成率**：事先选定的近期软件完整离线包中，完整提取的数量/总数，包括尚未支持的家族，不能从分母里删除失败样本。
3. **结果分布**：完整、仅外层、部分、不支持、外部内容缺失、错误；按格式与发布年份分组。
4. **错误归类准确性**：缺卷、密码、未知版本、损坏等是否识别正确，不能仅看未崩溃。

在线引导器和差分包另设挑战集合并公开结果，不计入离线完整包完成率，但也不能从报告中隐藏。测试集修改时记录变化，避免更换简单样本制造提升。

## 7. 测试方法与发布记录

自动测试集中在有意义的解析与写入行为：整数溢出/边界读取、结构版本、路径映射、CRC/哈希、固实流和冲突。对自写的 Inno/NSIS 等二进制读取入口进行变异与模糊测试；不为每个配置字段或静态文案建立镜像测试。

基准优先使用“打包前目录 + 文件哈希”，参考工具仅作交叉检查。真实 Windows 验证拖拽、通知、进程退出、文件权限和长路径，这些不能由编译或静态审查替代。

每次发布记录自有源码版本、模块能力、基础库版本/许可、样本报告、已知限制、实际运行依赖和便携包 SHA-256。遇到新版本安装器，先做最小复现和结构差异分析，再添加分支，保留旧有近期样本回归。
